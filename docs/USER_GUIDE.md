# Player and host guide

## Play without a wallet

Choose **Practice solo** on a topic card, enter your name and start. Practice begins with a countdown and includes five 20-second questions. It is a personal sprint without fake opponents. Read the explanations afterwards.

For a shared battle, select **Create a battle**, choose a pack and title, and share the lobby's six-character code or URL. Friends select **Join with a code** or follow the invite. The host waits for another player, then selects **Start battle**. A lone host can select **Start solo practice** in an unsponsored room.

## During and after a battle

Pick one option for each question. Your choice locks; you cannot change it or answer after the server advances. Wrong and missed answers earn zero. Scores update after each question ends, so a locked answer may not change your displayed total immediately.

After the fifth question, read the leaderboard and recap. Tied top scores share first place. Hosts can open concept insights to see what the group should review next. **Results** downloads JSON. **My learning** shows history for your saved browser session.

## When Start is unavailable

- Only the host's original browser session can start the room.
- Sponsored rooms need two or more players, every wallet linked, and confirmed registered funding.
- Unsponsored one-player rooms offer solo practice.
- A room cannot restart after it has begun. Use **Play again** to create a new one.
- The session fix preserves current ownership across refreshes. It cannot recover a token that was already lost; create a fresh room if an old room shows you as a spectator.

## Sponsored rooms

Follow [Rewards](REWARDS.md). Each player uses their own wallet and browser session. Signing the link challenge associates an address with the room; it does not transfer tokens. Funding, settlement, claim and refund are separate wallet-approved transactions.

## Browser storage

Player identity, display name, saved contract address and local transaction receipts use browser storage. Keep the original browser profile until you finish hosting and claiming. Clearing site data loses the session credential. Anyone with that credential can act as the player, so do not share it in screenshots or bug reports.

The live site is configured for public access. Public room data includes participant names and linked addresses. Use a display name you are comfortable making public.
